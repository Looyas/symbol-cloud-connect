# Changelog (GCP)

Template versions follow `gcp-v<MAJOR>.<MINOR>.<PATCH>` (git tags; Symbol pins tag and
commit). Releases are immutable. Any change to a granted role is listed under
**Permissions**.

## gcp-v2.0.2

### Fixed
- Security posture verification failed on `storage.buckets.get`: the scanner reads
  each bucket's configuration (`get_bucket`, CIS section 5), and none of
  `roles/viewer`, `roles/iam.securityReviewer`, `roles/cloudasset.viewer` grants it.

### Permissions
- **security**: `roles/storage.bucketViewer` at the scope for the observability
  identity (`storage.buckets.get` / `storage.buckets.list`: bucket metadata only, no
  object listing or reading). Re-running the setup adds this one grant and keeps the
  keys; paste the new connection code (it names gcp-v2.0.2).

## gcp-v2.0.1

### Fixed
- `--allow-key-creation-exception` aborted the apply with *Provider produced
  inconsistent final plan* on `module.key_policy.time_sleep.propagation[0]`. Its
  trigger was built from `google_org_policy_policy.name`, which the google provider
  rewrites to its short form (`iam.disableServiceAccountKeyCreation`) during apply.
  The trigger (and the `ready` output) are now built from the project and the
  constraint names, known at plan time; the pause still waits for the policies
  (`depends_on`). A failed gcp-v2.0.0 apply resumes from its state when the new
  command runs: the policies already created are kept (the provider compares
  `name` by its last segment), and nothing is recreated.

### Permissions
- Unchanged.

## gcp-v2.0.0

**Breaking.** One identity model: two service accounts in the customer project with a
key generated by Google, delivered to Symbol in the connection code. Symbol's GCP
project is no longer involved.

### Changed
- `modules/identity`: `symbol-finops` / `symbol-observability` are always created (one
  per needed identity), each with ONE Google-generated key (`KEY_ALG_RSA_2048`,
  `TYPE_GOOGLE_CREDENTIALS_FILE`, `create_before_destroy`). A key is replaced only when
  its `key_rotation_ids` entry changes.
- Connection code **version 2**: prefix `SYMBOL-GCP-2.`, field `key.<identity>` =
  `{service_account, key_id, valid_after, valid_before, credentials}` (the key file).
  The output is **sensitive**; the size limit is 16384 characters.
- `symbol-setup.sh`: prints the code once with a "secret" banner; deletes the saved plan
  on success and on failure; keeps the rotation ids of the previous run.

### Added
- `modules/key-policy`: reads the effective `iam.disableServiceAccountKeyCreation` and
  `iam.managed.disableServiceAccountKeyCreation` on the project (Org Policy v2
  `getEffectivePolicy`). `terraform_data.key_creation_gate` stops the plan before
  anything is created when one is enforced; check `key_creation_policy_readable` warns
  when they cannot be read.
- Variable `allow_key_creation_exception` / flag `--allow-key-creation-exception`: a
  project-level exception (`enforce: false`) for both constraints, a 90 s propagation
  pause before the keys, removed by `--destroy`.
- Variable `key_rotation_ids` / flag `--rotate finops|observability`.
- `symbol-setup.sh` step 4 checks the key-creation policy before Terraform runs and
  prints the exact commands for an Organization Policy Administrator.
- Provider `hashicorp/time` 0.13.1 (lock file updated for every platform).
- `tests/reveal`: test-only helper that prints a run's sensitive code for the Python
  cross-checks.

### Removed
- Identity modes `symbol_principal` and `key_upload`; variables `identity_mode`,
  `finops_principal`, `observability_principal`, `finops_certificate_url`,
  `observability_certificate_url`; flags `--identity-mode`, `--finops-principal`,
  `--observability-principal`, `--cert-base-url`; the certificate downloads.

### Permissions
- The administrator now always needs `roles/iam.serviceAccountAdmin` and
  `roles/iam.serviceAccountKeyAdmin` on the project; `roles/orgpolicy.policyViewer` is
  recommended, `roles/orgpolicy.policyAdmin` (organisation) only for
  `--allow-key-creation-exception`.
- Roles granted to Symbol's identities: unchanged.

## gcp-v1.0.0

First release (CLOUD-SETUP-CONTRACT-V2 §5).

### Added
- `symbol-setup.sh`: Cloud Shell flow (project resolution, Terraform >= 1.5 check with a
  checksum- and signature-verified install of Terraform 1.16.6, bootstrap APIs,
  organisation and effective org-policy detection, automatic identity mode, billing
  export detection, GCS state bucket, plan / confirm / apply, framed connection code),
  `--destroy` (keeps the billing dataset and the state bucket), `--yes` for CI.
- Identity modes `symbol_principal` (grants to Symbol's per-org service accounts) and
  `key_upload` (service accounts `symbol-finops` / `symbol-observability` with Symbol's
  uploaded certificate as their only key).
- **finops**: APIs, dataset `billing_export` when absent, FOCUS view `gcp_focus_v1` over the
  detailed usage cost export (Google's FOCUS v1.0 GA mapping, column names of Symbol's
  reader), grants.
- **monitoring**: topic `symbol-monitoring`, subscription `symbol-monitoring-sub` (ack 60 s,
  retention 7 days, no expiry), audit-log sink `symbol-audit-sink` at project, folder or
  organisation level; optional SCC v2 notification `symbol-scc` with topic `symbol-scc`
  and subscription `symbol-scc-sub`.
- **security**: read-only scanner grants at the chosen scope.
- **finops** scope grants include `roles/storage.bucketViewer` (bucket metadata only) for
  inventory-collector's `storage.buckets.get`.
- Outputs `symbol_connection_code` (`SYMBOL-GCP-1.` + unpadded base64url JSON, §5.7) and
  `symbol_connection_summary`.
- Labels `symbol-managed`, `symbol-org`, `symbol-template` on every labelled resource.
- Committed provider lock file (google 8.7.0, http 3.6.2).
