# Permissions granted by the stack (oci-v1.0.1)

All policies are attached to the **root compartment** and created in the **home region**.
`<C>` stands for `where request.networkSource.name='symbol'`: the statement only applies to
requests coming from Symbol's published egress IPs (network source `symbol`).

Symbol's service identities are **service users** in the Default identity domain. They
cannot sign in to the console, have no password, and can only use API keys. The key pairs
are generated by Symbol, and the private keys never leave Symbol.

## signin: no policy

The `Symbol Integration` application has **no app role** and **no grant**. That rules out
Identity Domain Administrator and every other admin role. Users who sign in through Symbol
get a UPST with **their own** OCI permissions. Symbol creates no policy for them.

| Object | Setting | Reason |
|---|---|---|
| App `Symbol Integration` | confidential (or trusted with `CLIENT_ASSERTION`), grants `authorization_code`, `client_credentials`, `refresh_token`, one redirect URI | Sign-in code flow; `client_credentials` lets Symbol verify the client without any role |
| Trust `Symbol-Trust` | JWT, issuer = Symbol, Symbol certificate, `sub` -> `userName`, `client_id` must be `symbol-broker`, OAuth client = the app only, **no impersonation** | Exchanges a Symbol-signed token for the signed-in user's own UPST |

## finops: `symbol-finops-policy`

| Statement | Reason |
|---|---|
| `define tenancy usage-report as ocid1.tenancy.oc1..aaaaaaaaned4fkpkisbwjlr56u7cj63lf3wffbilvqknstgtvzub7vhqkggq` | Names Oracle's tenancy that hosts your cost and usage reports. `define` cannot have a condition. |
| `endorse group symbol-finops to read objects in tenancy usage-report` | Read the FOCUS cost reports (bucket `bling`). Kept without `<C>`, as in the design (see note below). |
| `allow group symbol-finops to inspect tenancies in tenancy <C>` | Read tenancy metadata (`get_tenancy` health check, home region). |
| `allow group symbol-finops to inspect all-resources in tenancy <C>` | Resource inventory (Search) for cost allocation. Lists names and metadata, not contents. |
| `allow group symbol-finops to read buckets in tenancy <C>` | Storage inventory and cost attribution. |
| `allow group symbol-finops to inspect objects in tenancy <C>` | Object counts and sizes for storage cost; object contents are **not** readable. |
| `allow group symbol-finops to read volume-family in tenancy <C>` | Block-volume inventory (unattached volumes, sizing). |
| `allow group symbol-finops to read audit-events in tenancy <C>` | Attribute cost changes to the events that caused them. |
| `allow group symbol-finops to read optimizer-api-family in tenancy <C>` | Cloud Advisor recommendations (Cloud Advisor must be enabled). |

## monitoring: `symbol-observability-policy` (part) and `symbol-events-policy`

| Statement | Reason |
|---|---|
| `allow group symbol-observability to use stream-pull in compartment id <monitoring compartment> <C>` (`in tenancy` when the stream is in the root) | Consume the Symbol stream: `GetMessages`, `CreateCursor`, `CreateGroupCursor`, `ConsumerCommit`/`Heartbeat`. Cannot write and cannot read other streams' metadata. |
| `allow group symbol-observability to read cloud-guard-family in tenancy <C>` | Backfill of Cloud Guard problems that were already open (`ListProblems`). |
| `allow service cloudEvents to use stream-push in compartment id <monitoring compartment>` (policy `symbol-events-policy`) | Lets the OCI Events service write matching events into the stream (`PutMessages` only). A service principal statement, so no network-source condition. |

Cloud Guard (only when `create_cloud_guard = auto` and Cloud Guard is disabled, or enabled
with no target at all): Cloud Guard is enabled with the home region as reporting region,
and target `symbol-cloud-guard-root` is created on the root compartment with Oracle-managed
recipes (configuration detector, activity detector, responder). These are created with
**your** permissions during Apply. Symbol's identities get no write access to Cloud Guard.

## security: `symbol-observability-policy` (part)

Scope `<S>` = `tenancy`, or `compartment id <scan_compartment_id>` if you set one.

| Statement | Reason (CIS OCI Foundations checks) |
|---|---|
| `allow group symbol-observability to inspect compartments in <S> <C>` | Enumerate compartments to scan |
| `allow group symbol-observability to inspect groups in <S> <C>` | Admin group membership checks |
| `allow group symbol-observability to inspect policies in <S> <C>` | Over-broad policy checks |
| `allow group symbol-observability to read users in <S> <C>` | MFA, API key age and credential checks |
| `allow group symbol-observability to inspect virtual-network-family in <S> <C>` | Security lists / NSGs open to 0.0.0.0/0 |
| `allow group symbol-observability to inspect instance-family in <S> <C>` | Instance metadata service, boot volume encryption flags |
| `allow group symbol-observability to inspect volume-family in <S> <C>` | Volume encryption (CMK) |
| `allow group symbol-observability to inspect database-family in <S> <C>` | Database exposure and encryption |
| `allow group symbol-observability to read buckets in <S> <C>` | Public buckets, bucket encryption and versioning |
| `allow group symbol-observability to read log-groups in <S> <C>` | Logging configuration |
| `allow group symbol-observability to inspect alarms in <S> <C>` | Monitoring/alerting checks |
| `allow group symbol-observability to inspect tag-namespaces in <S> <C>` | Tagging governance |
| `allow group symbol-observability to inspect usage-budgets in <S> <C>` | Budget presence |
| `allow group symbol-observability to inspect vaults in <S> <C>` | Vault presence |
| `allow group symbol-observability to inspect keys in <S> <C>` | Key rotation checks |
| `allow group symbol-observability to read cloud-guard-family in <S> <C>` | Cloud Guard enabled check (deduplicated with monitoring) |

Users and groups only exist in the root compartment. With a compartment scope, the identity
checks return no data.

## Notes

- The `endorse` statement has no network-source condition, matching the design. Endorse
  statements do accept conditions, but whether `request.networkSource` is evaluated on this
  cross-tenancy request is still unverified. It is a hardening candidate for a later
  version, once tested.
- `symbol-events-policy` may not be strictly required (Oracle's documentation does not list
  a service policy for in-tenancy Events delivery). It is kept because it grants a single
  write-only operation on the monitoring compartment.
